# `String::insert`

**Level:** reference · for working programmers

**One line:** Inserts one `char` at a byte offset, shifting everything after it — **O(n)**, and it panics off a character boundary.

```text
pub fn insert(&mut self, idx: usize, ch: char)
```

Stable since **1.0.0**.

The index is a byte offset, with the same two panics as slicing: out of range, or inside a character. `s.insert(0, c)` is always legal; `s.insert(s.len(), c)` is [`push`](../string_push/README.md).

Everything after the offset moves, so inserting at the front of a long string in a loop is quadratic. Building in order and using `push_str`, or collecting an iterator, is almost always better.

The argument is a `char`; [`insert_str`](../string_insert_str/README.md) takes text.

A very common misuse is treating the index as a character position. On non-ASCII text it is not, and the offset has to come from [`char_indices`](../../str_methods/str_char_indices/README.md).

## Example

<!-- source:string_insert -->
*[`string_insert.rs`](examples/string_insert.rs) in full — pasted here by `tools/run_examples.py` from the file CI compiles and runs.*

```rust
fn main() {
    let mut s = String::from("hello");
    s.insert(0, '>');
    s.insert(3, '-');
    println!("{s:?}");

    // At the end, it is push.
    let n = s.len();
    s.insert(n, '!');
    println!("{s:?}");

    // Byte offsets, not character positions.
    let mut accented = String::from("héllo");
    println!("boundary at 2? {}", accented.is_char_boundary(2));
    let third = accented.char_indices().nth(2).unwrap().0;
    accented.insert(third, '-');
    println!("{accented:?}");

    // Everything after the offset shifts, so this is O(n).
    let mut reversed = String::new();
    for c in "abcd".chars() {
        reversed.insert(0, c);
    }
    println!("{reversed:?}");

    // The linear way to do the same thing.
    println!("{:?}", "abcd".chars().rev().collect::<String>());
}
```
