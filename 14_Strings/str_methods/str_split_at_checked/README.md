# `str::split_at_checked`

**Level:** reference · for working programmers

**One line:** [`split_at`](../str_split_at/README.md) returning `Option` — `None` for an offset that is out of range **or** inside a character.

```text
pub const fn split_at_checked(&self, mid: usize) -> Option<(&str, &str)>
```

Stable since **1.80.0**. Usable in a `const` context.

Same cut, no panic. The two failure modes collapse into one `None`, so this is the form to use on any offset that came from outside your program: a config value, a terminal width, a byte count from a protocol.

`None` does not tell you *which* failure happened. When that matters, ask [`is_char_boundary`](../str_is_char_boundary/README.md) and compare against [`len`](../str_len/README.md) yourself.

When you want a cut *near* a requested offset rather than a refusal, [`floor_char_boundary`](../str_floor_char_boundary/README.md) moves the index back to the nearest legal one — the usual answer for truncating a display string.

## Example

<!-- source:str_split_at_checked -->
*[`str_split_at_checked.rs`](examples/str_split_at_checked.rs) in full — pasted here by `tools/run_examples.py` from the file CI compiles and runs.*

```rust
fn main() {
    let s = "héllo";

    for mid in [0, 1, 2, 3, 5, 6, 99] {
        println!("{mid:>2} -> {:?}", s.split_at_checked(mid));
    }

    // Distinguishing the two refusals, when it matters.
    for mid in [2, 99] {
        let why = if mid > s.len() { "out of range" } else { "inside a character" };
        println!("{mid} refused: {why}");
    }

    // Truncating to a budget: floor the offset rather than refusing.
    let budget = 3;
    let cut = s.floor_char_boundary(budget);
    println!("{:?}", s.split_at(cut));
}
```
