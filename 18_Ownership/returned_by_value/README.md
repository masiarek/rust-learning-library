# Returned by value: the caller needs a size

**Level:** 201 · working knowledge · companions: [every error](../returned_by_value_errors/README.md) · [lints](../returned_by_value_lints/README.md) · [reading](../returned_by_value_resources/README.md)

**One line:** A function that returns *by value* hands back the value itself, not its address, into room the caller set aside before the call. The caller is compiled once, so that room needs one size. `str`, `[T]` and `dyn Trait` don't have one. That is why `-> str` is refused, and why `str` can never be `Clone`.

```rust
fn first_word(s: &str) -> &str {      // 2 words come back: an address and a length
    s.split(' ').next().unwrap_or("")
}

fn shout(s: &str) -> String {         // 3 words come back; the text stays on the heap
    s.to_uppercase()
}

// fn trimmed(s: &str) -> str { … }   // E0277: the return type needs a size known at compile time
```

## Who reserves the room

The caller's machine code for `let w = shout("hi");` is fixed at compile time, long before `shout` runs. It sets aside room for `w`, and the room is `size_of::<String>()`: 3 words, whatever the text turns out to be. `shout` then fills that room. Nothing runs the function first to find out how big its answer is.

So each return type needs one size, known when the *caller* is compiled:

Part 1 is the rule. Each of the first five rows is one number for every value of the type. The `str` row has two values of one type with two sizes, `"hi"` and `"hello"`, so there is no number for the caller to reserve ([`str` is unsized](../../14_Strings/str_is_unsized/README.md#the-size-belongs-to-the-value)). Every return type carries the `Sized` bound you never typed, the same one every generic `T` does ([Some types have no size](../../12_Traits/how_to_learn_to_owned/types_with_no_size/README.md#sized-is-the-bound-you-never-wrote)).

Parts 2 and 3 separate *by value* from *copies everything*. By value means the value's own bytes come back, not an address. For an array those bytes are the elements. For a `String` they are the three-word header: the text stays in its heap buffer, the same way it did when the `String` went *in* as an argument in [The call stack's practice](../the_call_stack/README.md#practice). Part 4 is [why `str` is not `Clone`](#why-str-is-not-clone), below.

## What the machine does with it

There are two ways to hand the value back: in registers, or written into the caller's reserved room through an address the caller passes in as a hidden first argument. Which one a type gets is not simply its size. These eight functions, compiled to LLVM IR ([LLVM and its IR](../../20_Compilers/llvm_and_its_ir/README.md) explains the format):

```rust
#[unsafe(no_mangle)]
#[inline(never)]
pub fn number() -> u64 {
    7
}

#[unsafe(no_mangle)]
#[inline(never)]
pub fn two_numbers() -> (u64, u64) {
    (7, 8)
}

#[unsafe(no_mangle)]
#[inline(never)]
pub fn text() -> &'static str {
    "hello"
}

#[unsafe(no_mangle)]
#[inline(never)]
pub fn two_array() -> [u64; 2] {
    [7, 8]
}

#[unsafe(no_mangle)]
#[inline(never)]
pub fn three_numbers() -> (u64, u64, u64) {
    (7, 8, 9)
}

#[unsafe(no_mangle)]
#[inline(never)]
pub fn owned() -> String {
    String::from("hello")
}

#[unsafe(no_mangle)]
#[inline(never)]
pub fn bytes() -> [u8; 1000] {
    [7; 1000]
}

#[unsafe(no_mangle)]
pub fn caller() -> u64 {
    let (a, b, c) = three_numbers();
    a + b + c
}
```

```sh
rustc --edition 2024 --crate-type lib -C opt-level=0 -C debuginfo=0 --emit llvm-ir returns.rs
```

```text title="rustc 1.98.0, x86_64-apple-darwin, opt-level=0 — the define lines, sorted by name"
define void @bytes(ptr sret([1000 x i8]) align 1 %_0) unnamed_addr #3 {
define i64 @caller() unnamed_addr #4 {
define i64 @number() unnamed_addr #3 {
define void @owned(ptr sret([24 x i8]) align 8 %_0) unnamed_addr #3 {
define { ptr, i64 } @text() unnamed_addr #3 {
define void @three_numbers(ptr sret([24 x i8]) align 8 %_0) unnamed_addr #3 {
define void @two_array(ptr sret([16 x i8]) align 8 %_0) unnamed_addr #3 {
define { i64, i64 } @two_numbers() unnamed_addr #3 {
```

| Signature | Its IR return | How it comes back |
|---|---|---|
| `-> u64` | `i64` | one register |
| `-> (u64, u64)` | `{ i64, i64 }` | two registers |
| `-> &'static str` | `{ ptr, i64 }` | two registers: the address, then the length |
| `-> [u64; 2]` | `void`, and a parameter `ptr sret([16 x i8])` | written through a pointer to 16 bytes the caller reserved, although it is two words like the row above |
| `-> (u64, u64, u64)` | `void`, and `ptr sret([24 x i8])` | the same, 24 bytes |
| `-> String` | `void`, and `ptr sret([24 x i8])` | the same: a `String` header is 24 bytes here |
| `-> [u8; 1000]` | `void`, and `ptr sret([1000 x i8])` | the same, 1000 bytes |

One number or a pair of them came back in registers; the two-word array did not, and neither did anything bigger. `sret` is LLVM's name for the hidden argument: *structure return*. Either way the size is written into the function's own signature — `i64`, `{ ptr, i64 }`, `[1000 x i8]`. For `-> str` there would be no number to write there.

The assembly shows both halves. `caller` reserves the room and passes its address in `rdi`. `three_numbers` writes through `rdi` and never allocates anything:

```sh
rustc --edition 2024 --crate-type lib -C opt-level=1 -C debuginfo=0 --emit asm -C llvm-args=-x86-asm-syntax=intel returns.rs
```

```text title="rustc 1.98.0, x86_64-apple-darwin, opt-level=1 — three functions, .cfi lines removed"
_caller:
	push	rbp
	mov	rbp, rsp
	sub	rsp, 32
	lea	rdi, [rbp - 24]
	call	_three_numbers
	mov	rax, qword ptr [rbp - 16]
	add	rax, qword ptr [rbp - 24]
	add	rax, qword ptr [rbp - 8]
	add	rsp, 32
	pop	rbp
	ret

_three_numbers:
	push	rbp
	mov	rbp, rsp
	mov	rax, rdi
	mov	qword ptr [rdi], 7
	mov	qword ptr [rdi + 8], 8
	mov	qword ptr [rdi + 16], 9
	pop	rbp
	ret

_bytes:
	push	rbp
	mov	rbp, rsp
	push	rbx
	push	rax
	mov	rbx, rdi
	mov	edx, 1000
	mov	esi, 7
	call	_memset
	mov	rax, rbx
	add	rsp, 8
	pop	rbx
	pop	rbp
	ret
```

- `sub rsp, 32` then `lea rdi, [rbp - 24]`: the caller makes room on its own stack frame and passes the address of that room.
- `mov qword ptr [rdi + 16], 9`: the callee's answer goes directly into the caller's frame.
- `mov edx, 1000`: in `bytes` the size is a constant in the machine code, the length `memset` gets. A `str` has no such constant.

Where the callee *builds* the value depends on the build. A function that fills a local `[u64; 64]` and returns it gets, at `opt-level=0`, a 512-byte `alloca` for the local and a `memcpy` of 512 bytes into the `sret` room at the end. At `opt-level=1` and `3` the `sret` parameter itself is named `%t`, the local: the array is built in the caller's room and nothing is copied. (rustc 1.98.0, x86_64-apple-darwin, LLVM IR.) Either way the value ends in room the caller reserved.

This is what rustc 1.98.0 chose for this target. The Reference says of Rust's own calling convention that it *"offers no stability guarantees"* ([ABI ↗](https://doc.rust-lang.org/reference/items/external-blocks.html#abi)), so where the line between registers and `sret` falls may change. A function marked `extern "C"` follows the platform's published C rules instead. The *need for a size* does not change, because both ways need one before the call: a register has a fixed width, and reserved room has a length.

## So `-> str` has no signature

```text title="Abridged — return_str.rs, rustc 1.98.0, the first of its two errors"
error[E0277]: the size for values of type `str` cannot be known at compilation time
 --> return_str.rs:1:27
  |
1 | fn first_word(s: &str) -> str {
  |                           ^^^ doesn't have a size known at compile-time
  |
  = help: the trait `Sized` is not implemented for `str`
  = note: the return type of a function must have a statically known size
```

(The body in that file was `*s`, which is a second error, `E0507`; [every error](../returned_by_value_errors/README.md#1-str) shows both.)

The same is true of every unsized type, and the fix is always the same: return something sized that *leads to* the unsized value.

| Instead of | Return | What comes back | Who owns the bytes |
|---|---|---|---|
| `-> str` | [`&str`](../../14_Strings/string_vs_str/README.md) | 2 words | the caller's data, borrowed: it must outlive the result |
| `-> str` | [`String`](../../14_Strings/making_a_string/README.md) | 3 words | the result, in a new heap buffer that can grow |
| `-> str` | [`Box<str>`](../../14_Strings/boxed_str/README.md) | 2 words | the result, in a heap buffer of exactly that length |
| `-> [T]` | `&[T]`, `Vec<T>`, `Box<[T]>` | 2, 3, 2 words | as the three rows above |
| `-> dyn Trait` | [`impl Trait`](../../12_Traits/returning_a_trait/README.md) | the concrete type's size | the result, and the compiler knows which type |
| `-> dyn Trait` | [`Box<dyn Trait>`](../../12_Traits/returning_a_trait/README.md) | 2 words: address and vtable | the result, on the heap |

Parameters are the same question in the other direction. `fn count(s: str)` is the same `E0277`, and there rustc suggests the fix itself: *"function arguments must have a statically known size, borrowed types always have a known size"*, with `&str` as the help.

## Why `str` is not `Clone`

```rust
pub trait Clone: Sized {
    fn clone(&self) -> Self;
}
```

`-> Self` is a return by value. A `str` could never be handed back that way, and std writes the requirement onto the trait line itself as the supertrait `: Sized`. So there is no `impl Clone for str`, and there can't be ([Step 4 of the `ToOwned` path](../../12_Traits/how_to_learn_to_owned/clone_returns_self/README.md#self-in-self-out)).

What `name.clone()` on a `&str` does instead is part 4 of the output above. The call finds the reference's own `Clone`, which copies the two words ([Reading the `Clone for &T` hover](../../12_Traits/reading_the_clone_hover/README.md) reads that impl line by line). rustc flags it:

```text title="Abridged — clone_str.rs, rustc 1.98.0, the warning without its summary line"
warning: call to `.clone()` on a reference in this situation does nothing
 --> clone_str.rs:3:20
  |
3 |     let copy = name.clone();
  |                    ^^^^^^^^ help: remove this redundant call
  |
  = note: the type `str` does not implement `Clone`, so calling `clone` on `&str` copies the reference, which does not do anything and can be removed
  = note: `#[warn(noop_method_call)]` on by default
```

`ToOwned` exists for this gap. Its method returns `Self::Owned`, a *different* type that is sized, so `str` can implement it and hand back a `String` ([`ToOwned` is `Clone` with a separate owned type](../../12_Traits/how_to_learn_to_owned/clone_vs_to_owned/README.md)).

## A common explanation, checked

One explanation of that warning reads: *"The warning explains it: `str` does not implement `Clone`, because it's unsized and can't be returned by value. So there's no `str::clone` for auto-deref to find. The only `clone` in scope is the one on the reference type."* Four claims, run:

| Claim | Verdict | What rustc 1.98.0 shows |
|---|---|---|
| "The warning explains it" | **half** | The warning's note says `str` does not implement `Clone`. It gives no reason. The reason is in `Clone`'s declaration, `pub trait Clone: Sized`. |
| "`str` is not `Clone` because it is unsized and can't be returned by value" | **true** | `clone` returns `Self` by value, and `-> str` is `E0277` with *"the return type of a function must have a statically known size"*. |
| "no `str::clone` for auto-deref to find" | **right conclusion, wrong mechanism** | No dereference is involved. For `name: &str` the first receiver type tried is `&str` itself, which is exactly `str::clone`'s receiver type (`&self` on `str`). Had it existed, it would have matched first. The reference's `clone` is found one step later, at `&&str`, by adding a `&`, not by removing one. [The dot takes the first receiver that fits](../../12_Traits/how_to_learn_to_owned/the_dot_picks_first/README.md#walk-it-for-clone) walks the list. |
| "the only `clone` in scope is the one on the reference type" | **loose** | *In scope* is about which traits are imported, and `Clone` is in the prelude either way. The accurate version: it is the only `clone` method lookup can find. |

## If you are coming from another language

**C.** The same machinery, with one hole Rust does not have. A C function cannot return an array at all: `int make(void)[3];` is *"function cannot return array type 'int[3]'"* (Apple clang 21), and the workaround is to wrap it, `struct Triple { int v[3]; }`, which comes back whole. Rust's `-> [u8; 1000]` needs no wrapper, because a Rust array keeps its length in its type; a C array passed to a function decays to a pointer and loses it ([the C library on that decay ↗](https://masiarek.github.io/c-learning-library/03_Strings/a_string_is_bytes_up_to_a_nul/index.html#what-the-four-cases-show)). C has no unsized return either: a `char *` is the `&str` of C without the length. And `return &local;` is a warning C lets you build past, where Rust stops with `E0515` ([A stack slot is reused](../a_stack_slot_is_reused/README.md#what-rust-does-instead)).

**C++.** C++17 made *copy elision* part of the language: returning a prvalue constructs it straight in the caller's room. A type with its copy and move constructors deleted can be returned from `Pinned make() { return Pinned(); }` under `-std=c++17` and is *"call to deleted constructor of 'Pinned'"* under `-std=c++14` (Apple clang 21). Rust promises nothing of the kind, and needs no promise: a move is a byte copy that runs no user code, so whether rustc builds in place (it does at `opt-level=1`, above) changes speed, never behaviour.

**Python.** Nothing is returned by value. `return result` hands back a reference to an object on the heap, so the caller's name and any other name for that object see the same changes. The size question never comes up, which is also why Python needs *"a buffer the caller owns and the callee may write into"* spelled out by hand for `readinto` and `recv_into` ([the Python library on `bytearray` ↗](https://masiarek.github.io/python-learning-library/01_Text_and_Bytes/bytearray_is_mutable/index.html)): that is the `sret` pattern, written as an argument.

**Go.** Structs are returned by value, as here. The difference is returning an address: `p := Point{1, 2}; return &p` compiles, and `go build -gcflags=-m` reports *"moved to heap: p"* (Go 1.25.5) — escape analysis quietly promotes the local to the heap. Rust never moves a value to the heap behind your back, so the same line is `E0515`, and the fix is the one this page is about: return the `Point` itself.

**Java.** Primitives come back by value; everything else is a reference, as in Python — a returned `int[]` is the same array the callee kept. The JVM decides where objects live, so there is no unsized-return error to meet.

## Practice

**Three ways around `-> str`.** `fn trimmed(s: &str) -> str { … }` is refused. Write it three times, returning `&str`, `String` and `Box<str>`. For each, print how many words came back, and whether the result points into the input's bytes. Then `drop` the input: which results can you still print, and what does rustc say about the one you can't?

```rust
//! Kata solution: `fn trimmed(s: &str) -> str` is refused. Three signatures
//! that compile, and what each one hands back.
//!
//! Every answer is a size in words or a comparison of addresses, never an
//! address, so the answer key is the same on every run and every target.
//!
//!   rustc --edition 2024 returned_by_value_kata.rs -o /tmp/rbvk && /tmp/rbvk

use std::mem::size_of;

fn words<T>() -> usize {
    size_of::<T>() / size_of::<usize>()
}

/// Borrows: the result is a window onto the caller's text.
fn trimmed_borrowed(s: &str) -> &str {
    s.trim()
}

/// Owns, with room to grow: the text is copied into a new buffer.
fn trimmed_string(s: &str) -> String {
    s.trim().to_string()
}

/// Owns, fixed length: the text is copied, and the capacity word is gone.
fn trimmed_boxed(s: &str) -> Box<str> {
    s.trim().into()
}

/// Does `part` start inside `whole`'s bytes?
fn points_into(part: &str, whole: &str) -> bool {
    whole.as_bytes().as_ptr_range().contains(&part.as_ptr())
}

fn main() {
    let input = String::from("   hello   ");

    let a = trimmed_borrowed(&input);
    let b = trimmed_string(&input);
    let c = trimmed_boxed(&input);

    println!("input {input:?}");
    println!("   -> &str      {} words  {a:?}  points into the input: {}", words::<&str>(), points_into(a, &input));
    println!("   -> String    {} words  {b:?}  points into the input: {}", words::<String>(), points_into(&b, &input));
    println!("   -> Box<str>  {} words  {c:?}  points into the input: {}", words::<Box<str>>(), points_into(&c, &input));

    drop(input);
    println!("after drop(input), b and c still work: {b} {c}");
    // println!("{a}");  // E0505: cannot move out of `input` because it is borrowed
}
```

## Po polsku

**Zwracanie przez wartość** (*returned by value*) znaczy, że funkcja oddaje samą wartość, a nie jej adres. Wywołujący rezerwuje na nią miejsce jeszcze przed wywołaniem, a jego kod jest kompilowany raz, więc potrzebuje jednej liczby bajtów. `str`, `[T]` i `dyn Trait` takiej liczby nie mają: `"hi"` to 2 bajty, `"hello"` 5, a typ jest ten sam. Stąd `-> str` to błąd `E0277`.

Na maszynie widać to wprost. Do dwóch słów wraca w rejestrach (`&str` to adres i długość). Coś większego callee zapisuje pod adres miejsca zarezerwowanego przez wywołującego, przekazany jako ukryty argument (`sret` w LLVM IR, `rdi` na x86-64). Rozmiar jest zapisany w sygnaturze funkcji, np. `sret([24 x i8])` dla `String`.

„Przez wartość” nie znaczy „kopiuje wszystko”: `String` oddaje trzy słowa nagłówka, a tekst zostaje w tym samym buforze na stercie. Rozwiązania zamiast `-> str`: `&str` (pożyczone), `String` albo `Box<str>` (własne). Zamiast `-> dyn Trait`: `impl Trait` albo `Box<dyn Trait>`.

To samo tłumaczy, czemu `str` nie jest `Clone`. `fn clone(&self) -> Self` zwraca `Self` przez wartość, a `Clone: Sized` zapisuje ten wymóg w deklaracji traitu. `.clone()` na `&str` kopiuje więc referencję (ostrzeżenie `noop_method_call`), a `String` daje `to_owned()`.

**Szukaj po polsku:** zwracanie przez wartość · typ o nieznanym rozmiarze · `rust return str by value` · `rust sret` · `the size for values of type str cannot be known at compilation time` · `rust calling convention return value`
