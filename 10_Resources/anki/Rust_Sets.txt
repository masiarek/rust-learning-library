<code>a.intersection(&amp;b)</code> vs <code>&amp;a &amp; &amp;b</code> &mdash; what does each return, and what does each cost?	<b>The method borrows both sets and returns a lazy iterator of <code>&amp;T</code>; the operator clones the members into a brand-new set.</b><br><br>Nothing is allocated by the method until you <code>collect</code> &mdash; <code>.count()</code> or <code>.next()</code> never allocate at all. The operator needs <code>T: Clone</code>. <code>a.is_subset(&amp;a)</code> &mdash; true or false? And how do you ask for a <i>proper</i> subset?	<b>True: <code>is_subset</code> is &sube;, not &sub;.</b> The empty set is a subset of everything, too.<br><br>There is no proper-subset method: write <code>x.is_subset(&amp;y) &amp;&amp; x != y</code>. <code>is_disjoint</code> is <i>the intersection is empty</i>, answered without building it.<br><div style="opacity:.6; font-size:.8em; margin-top:8px;">verified — rustc 1.98.0, edition 2024</div><pre style="text-align:left; white-space:pre-wrap; font-size:0.92em; line-height:1.45; border-left:3px solid #7a7a7a; padding:2px 0 2px 10px; margin:10px 0; font-family:ui-monospace,SFMono-Regular,Menlo,Consolas,monospace;">use std::collections::BTreeSet;<br><br>fn main() {<br>    let a = BTreeSet::from([1, 2, 3]);<br>    let small = BTreeSet::from([2, 3]);<br>    let empty: BTreeSet&lt;i32&gt; = BTreeSet::new();<br>    println!(&quot;{} {} {}&quot;, a.is_subset(&amp;a), small.is_subset(&amp;a) &amp;&amp; small != a, empty.is_subset(&amp;small));<br>    println!(&quot;{}&quot;, a.is_disjoint(&amp;BTreeSet::from([9])));<br>}<br><br>// true true true<br>// true</pre><br><div style="opacity:.85; font-size:.95em; border-top:1px solid #9995; margin-top:12px; padding-top:8px;"><b>Python:</b> <code>a &lt;= b</code> is <code>is_subset</code>; <code>a &lt; b</code> is the proper subset Rust has no operator for.</div><br><div style="margin-top:10px; font-size:.9em;">&rarr; <a href="https://masiarek.github.io/rust-learning-library/26_Collections/set_operations/index.html">set_operations</a></div>	rust sets

Why does this library never <code>println!("{:?}", some_hash_set)</code>?	<b>The default hasher, <code>RandomState</code>, is seeded afresh for every process, so the same members print in a different order on each run.</b><br><br>Print through a <code>BTreeSet</code> (or a sorted <code>Vec</code>). When the order matters to the program itself, choose <code>BTreeSet</code> in the first place: needs <code>Ord</code>, O(log n), ordered always.<br><div style="opacity:.6; font-size:.8em; margin-top:8px;">verified — rustc 1.98.0, edition 2024</div><pre style="text-align:left; white-space:pre-wrap; font-size:0.92em; line-height:1.45; border-left:3px solid #7a7a7a; padding:2px 0 2px 10px; margin:10px 0; font-family:ui-monospace,SFMono-Regular,Menlo,Consolas,monospace;">use std::collections::{BTreeSet, HashSet};<br><br>fn main() {<br>    let h: HashSet&lt;i32&gt; = [3, 1, 2].into_iter().collect();<br>    let b: BTreeSet&lt;i32&gt; = h.iter().copied().collect();<br>    println!(&quot;{b:?} {}&quot;, h == [2, 3, 1].into_iter().collect());<br>}<br><br>// {1, 2, 3} true</pre><br><div style="opacity:.85; font-size:.95em; border-top:1px solid #9995; margin-top:12px; padding-top:8px;"><b>Python:</b> a set iterates the same way within one process for the same history, which tempts code to depend on it. Rust breaks that dependency on the first run.</div><br><div style="margin-top:10px; font-size:.9em;">&rarr; <a href="https://masiarek.github.io/rust-learning-library/26_Collections/set_operations/index.html">set_operations</a></div>	rust sets hashing
Deduplicate <code>vec![3, 1, 1, 2, 3, 1]</code> keeping first-seen order &mdash; and what does plain <code>dedup()</code> leave?	<b>A <code>HashSet</code> <code>seen</code> as the filter: <code>seen.insert(n)</code> is true the first time only.</b><br><br><code>sort()</code> + <code>dedup()</code> gives sorted order instead. <code>dedup()</code> alone removes ADJACENT repeats only.<br><div style="opacity:.6; font-size:.8em; margin-top:8px;">verified — rustc 1.98.0, edition 2024</div><pre style="text-align:left; white-space:pre-wrap; font-size:0.92em; line-height:1.45; border-left:3px solid #7a7a7a; padding:2px 0 2px 10px; margin:10px 0; font-family:ui-monospace,SFMono-Regular,Menlo,Consolas,monospace;">use std::collections::HashSet;<br><br>fn main() {<br>    let v = vec![3, 1, 1, 2, 3, 1];<br>    let mut seen = HashSet::new();<br>    let first: Vec&lt;i32&gt; = v.iter().copied().filter(|n| seen.insert(*n)).collect();<br>    let mut plain = v.clone();<br>    plain.dedup();<br>    println!(&quot;{first:?} {plain:?}&quot;);<br>}<br><br>// [3, 1, 2] [3, 1, 2, 3, 1]</pre><br><div style="opacity:.85; font-size:.95em; border-top:1px solid #9995; margin-top:12px; padding-top:8px;"><b>ABAP:</b> <code>DELETE ADJACENT DUPLICATES</code> has the same trap, and the same fix: <code>SORT</code> first.</div><br><div style="margin-top:10px; font-size:.9em;">&rarr; <a href="https://masiarek.github.io/rust-learning-library/26_Collections/set_operations/index.html">set_operations</a></div>	rust sets vec
