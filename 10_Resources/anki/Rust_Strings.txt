Rust has two text types. What is each one, in terms of what sits on the <b>stack</b>?	<b><code>&amp;str</code> = a borrowed view: pointer + length (16 bytes). <code>String</code> = an owned buffer: pointer + length + capacity (24 bytes).</b><br><br>Only <code>String</code> can grow, because only <code>String</code> owns the allocation. Everything about <i>reading</i> text lives on <code>str</code> — and a <code>String</code> gets all of it free, because it derefs to <code>str</code>.<br><div style="opacity:.85; font-size:.95em; border-top:1px solid #9995; margin-top:12px; padding-top:8px;"><b>Python:</b> one <code>str</code> type, always owned, always immutable. Rust splits <i>ownership</i> from <i>view</i>, which is the whole reason there are two types.<br><b>ABAP:</b> <code>DATA(lv_b) = lv_a</code> always copies. A <code>&amp;str</code> is the copy you did <i>not</i> make.</div><br><div style="margin-top:10px; font-size:.9em;">&rarr; <a href="https://masiarek.github.io/rust-learning-library/14_Strings/string_vs_str/index.html">string_vs_str</a></div>	rust strings core
