# Tables 2.1 and 2.2, run: numeric types and their bits

[*Rust in Action*, run](../README.md) › Chapter 2 › §2.3.2 · tables 2.1 and 2.2 have no file in the book's repository

**Level:** 101 → 201 · a companion to *Rust in Action*, chapter 2

**One line:** On rustc 1.98.0, table 2.2's three bit patterns for 20 are exactly what the compiler prints. Table 2.1 leaves out `i128` and `u128`, and it says `isize` and `usize` take the CPU's native width. They take the pointer width, which is 32 bits on some 64-bit CPUs and 16 bits on an 8-bit one.

1. **Table 2.2 matches.** The `f32` row reads as a sign bit of 0, then the exponent `10000011` (131, minus the bias of 127, is 4), then the fraction `0100…` (binary 1.01, or 1.25). 1.25 × 2⁴ = 20. → [What a float actually stores](../../../19_Numbers/what_a_float_stores/README.md)
2. **There are five integer widths, not four.** Table 2.1 stops at 64 bits. `i128` and `u128` have been stable since Rust 1.26.0, three years before the book; they are ordinary primitives and need no crate. → [What `i128` is exact about](../../../09_Advanced/i128_exactness/README.md)
3. **Unsigned types reach one more than twice as high, and they include zero.** The book says unsigned integers represent only positive numbers and go twice as high. `u8::MAX` is 255, which is 2 × 127 + 1, and `u8::MIN` is 0. The signed ranges are lopsided the other way: `i8` reaches −128 but only +127. → [A width is a promise](../../../15_First_Programs/values/README.md#a-width-is-a-promise-and-it-is-checked)
4. **The same eight bits read differently as signed and unsigned.** `11101100` is 236 as a `u8` and −20 as an `i8`: the negative of table 2.2's `i8` row, stored in two's complement. → [Two readings of the same eight bits](../../../19_Numbers/meet_the_byte/README.md#two-readings-of-the-same-eight-bits)
5. **The special float values are exponent patterns.** An exponent of all ones with a zero fraction is ±infinity, and all ones with a non-zero fraction is NaN. The book lists infinity, negative infinity and NaN. It leaves out negative zero, which has a bit pattern of its own.
6. **One number can have several bit patterns inside a single type, too.** Table 2.2 shows 20 in three types. Within `f32`, `0.0` and `-0.0` compare equal with different bits, and NaN has many patterns, none of which equals itself. → [NaN and the two missing traits](../../../19_Numbers/what_a_float_stores/README.md#the-part-that-belongs-to-rust-two-missing-traits)
7. **Floats do not hold real numbers, only a finite set of binary fractions.** The book says the float types represent real numbers. `0.1` is not one of those fractions, so an `f32` stores the nearest one, 0.100000001490116…. → [What a float actually stores](../../../19_Numbers/what_a_float_stores/README.md)

## `isize` and `usize` follow the pointer, not the CPU

std's own description of `usize` is the *pointer-sized* unsigned integer: as many bits as it takes to address any byte in memory. On most machines that is the CPU's word size, which is why table 2.1's description usually gives the right answer. These targets are where it does not:

| Target | CPU | `usize` bits |
|---|---|---|
| `x86_64-apple-darwin` | 64-bit x86 | 64 |
| `aarch64-apple-darwin` | 64-bit Arm | 64 |
| `x86_64-unknown-linux-gnux32` | 64-bit x86 | **32** |
| `aarch64-unknown-linux-gnu_ilp32` | 64-bit Arm | **32** |
| `wasm32-unknown-unknown` | WebAssembly | 32 |
| `i686-unknown-linux-gnu` | 32-bit x86 | 32 |
| `msp430-none-elf` | 16-bit MSP430 | 16 |
| `avr-none` | 8-bit AVR | **16** |

This table has no example program behind it, because `size_of::<usize>()` gives a different answer on each machine and [no answer key can hold it](../../../CONTRIBUTING.md). Each row comes from rustc 1.98.0's view of the target, which does not need the target installed:

```bash
rustc --print cfg --target x86_64-unknown-linux-gnux32
```

The line to read is `target_pointer_width="32"`. → [`usize` ↗](https://doc.rust-lang.org/std/primitive.usize.html), [Machine-dependent integer types ↗](https://doc.rust-lang.org/reference/types/numeric.html#machine-dependent-integer-types)

## Po polsku

Tabela 2.2 zgadza się co do bitu z tym, co wypisuje rustc 1.98.0: 20 jako `u32`, `i8` i `f32`. W wierszu `f32` widać znak 0, wykładnik `10000011` (131 − 127 = 4) i ułamek `0100…`, czyli 1,25 × 2⁴ = 20. Tabela 2.1 pomija za to `i128` i `u128`, stabilne od Rusta 1.26.0. Typy bez znaku obejmują też zero, a sięgają o jeden wyżej niż „dwa razy wyżej”: `u8::MAX` = 255 = 2 × 127 + 1.

`isize` i `usize` mają szerokość **wskaźnika** (*pointer width*), nie „natywną szerokość procesora”. Na `x86_64-unknown-linux-gnux32` 64-bitowy procesor ma 32-bitowy `usize`, a 8-bitowy AVR — 16-bitowy. Sprawdzisz to bez instalowania targetu: `rustc --print cfg --target <target>` i linia `target_pointer_width`. Liczby zmiennoprzecinkowe nie przechowują „liczb rzeczywistych”, tylko skończony zbiór ułamków dwójkowych: `0.1_f32` to naprawdę 0,100000001490116…. Mają też zero ujemne (`-0.0`, równe `0.0`, ale z innymi bitami) i wiele wzorców NaN, z których żaden nie jest równy sobie.
