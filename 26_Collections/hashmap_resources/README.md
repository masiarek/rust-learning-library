# `HashMap` and `HashSet`: resources

Beside [A first `HashMap`](../a_first_hashmap/README.md) and [A first `HashSet`](../a_first_hashset/README.md) · companions: [every error](../hashmap_errors/README.md) · [lints](../hashmap_lints/README.md)

**Level:** reference · the reading list

**One line:** Where the rest of the Rust world explains hash maps and sets: the Book's chapter and its six sections, what three books on the shelf say and where, the std pages that matter (`HashMap`, `HashSet`, `Entry`, the *which collection* table, `RandomState` and the HashDoS note, `Borrow`), the crate underneath (`hashbrown`) and the design it follows, the error codes, the lints, and three places to read with care — including §5.5–5.6 of *Rust: The Practical Guide*, which prints its maps unsorted and says `contains_key` returns an `Option`.

Every entry was checked on 2026-09-23 and every URL again on 2026-09-24: each answered 200 to `curl` (crates.io and the two publishers' sites refuse scripted requests, so `hashbrown` is linked at docs.rs and GitHub, and the book sections come from the books themselves), and each `#anchor` named here exists on its page. Book sections are copied from each book's own table of contents, read on this machine. The video's title was checked; it was not watched, so no timestamps are given. "Read with care" names a sentence that fails when run on rustc 1.98.0, and says what ran.

## If you read only four

- **[The Book, ch. 8.3 — *Storing Keys with Associated Values in Hash Maps* ↗](https://doc.rust-lang.org/book/ch08-03-hash-maps.html)**, in six sections: [Creating a New Hash Map ↗](https://doc.rust-lang.org/book/ch08-03-hash-maps.html#creating-a-new-hash-map), [Accessing Values in a Hash Map ↗](https://doc.rust-lang.org/book/ch08-03-hash-maps.html#accessing-values-in-a-hash-map) (`get`, `copied`, `unwrap_or`, and the loop *"in an arbitrary order"*), [Managing Ownership in Hash Maps ↗](https://doc.rust-lang.org/book/ch08-03-hash-maps.html#managing-ownership-in-hash-maps) (a `String` key is moved in; a `&str` key is borrowed), [Updating a Hash Map ↗](https://doc.rust-lang.org/book/ch08-03-hash-maps.html#updating-a-hash-map) with [Overwriting a Value ↗](https://doc.rust-lang.org/book/ch08-03-hash-maps.html#overwriting-a-value), [Adding a Key and Value Only If a Key Isn't Present ↗](https://doc.rust-lang.org/book/ch08-03-hash-maps.html#adding-a-key-and-value-only-if-a-key-isnt-present) (`entry` and `or_insert`) and [Updating a Value Based on the Old Value ↗](https://doc.rust-lang.org/book/ch08-03-hash-maps.html#updating-a-value-based-on-the-old-value) (the word-count loop, `*count += 1`), then [Hashing Functions ↗](https://doc.rust-lang.org/book/ch08-03-hash-maps.html#hashing-functions) (SipHash, and that a `BuildHasher` can replace it). The chapter is [A first `HashMap`](../a_first_hashmap/README.md) in the Book's order, without the return values.
- **[`std::collections::HashMap` ↗](https://doc.rust-lang.org/std/collections/struct.HashMap.html)**. The opening text is the part to read once: the default hasher is `RandomState`, chosen to resist HashDoS attacks at some cost in speed, and every key must satisfy `Eq` and `Hash` with the contract `k1 == k2 -> hash(k1) == hash(k2)`. Then the methods: [`insert` ↗](https://doc.rust-lang.org/std/collections/struct.HashMap.html#method.insert) (*"If the map did have this key present, the value is updated, and the old value is returned"*), [`get` ↗](https://doc.rust-lang.org/std/collections/struct.HashMap.html#method.get), [`contains_key` ↗](https://doc.rust-lang.org/std/collections/struct.HashMap.html#method.contains_key), [`entry` ↗](https://doc.rust-lang.org/std/collections/struct.HashMap.html#method.entry), [`remove` ↗](https://doc.rust-lang.org/std/collections/struct.HashMap.html#method.remove), [`iter` ↗](https://doc.rust-lang.org/std/collections/struct.HashMap.html#method.iter), [`keys` ↗](https://doc.rust-lang.org/std/collections/struct.HashMap.html#method.keys) and [`values` ↗](https://doc.rust-lang.org/std/collections/struct.HashMap.html#method.values).
- **[`std::collections` — *When Should You Use Which Collection?* ↗](https://doc.rust-lang.org/std/collections/index.html#when-should-you-use-which-collection)**, with [Use a `HashMap` when ↗](https://doc.rust-lang.org/std/collections/index.html#use-a-hashmap-when), [Use a `BTreeMap` when ↗](https://doc.rust-lang.org/std/collections/index.html#use-a-btreemap-when) and [Use the `Set` variant of any of these `Map`s when ↗](https://doc.rust-lang.org/std/collections/index.html#use-the-set-variant-of-any-of-these-maps-when). The same page has the [Performance ↗](https://doc.rust-lang.org/std/collections/index.html#performance) table — `HashMap` get, insert and remove are *O(1)~* expected, `BTreeMap` *O(log n)* — an [Entries ↗](https://doc.rust-lang.org/std/collections/index.html#entries) section on the `entry` API, and a worked [count of each character in a string ↗](https://doc.rust-lang.org/std/collections/index.html#counting-the-number-of-times-each-character-in-a-string-occurs). Its [Insert and complex keys ↗](https://doc.rust-lang.org/std/collections/index.html#insert-and-complex-keys) section is the rule behind [`mutable_key_type`](../hashmap_lints/README.md#mutable_key_type): a key must not change in a way that alters its hash or equality while it is in the map.
- ***Programming Rust*, 2nd ed.** (Blandy, Orendorff & Tindall, O'Reilly 2021), ch. 16 "Collections" → **"HashMap<K, V> and BTreeMap<K, V>"**, with "Entries" and "Map Iteration", then **"HashSet<T> and BTreeSet<T>"**, with "Set Iteration", "When Equal Values Are Different" and "Whole-Set Operations", then "Hashing" and "Using a Custom Hashing Algorithm". The most complete tour of the two APIs in a book, and the one that treats `entry` as a first-class subject rather than a footnote.

## Books

- ***Rust in Action*** (Tim McNamara, Manning 2021), ch. 7 "Files and storage" → **"Working with keys and values with HashMap and BTreeMap"** (p. 241): "Creating a HashMap and populating it with values", "Retrieving values from HashMap and BTreeMap", "How to decide between HashMap and BTreeMap", and "Adding a database index to actionkv v2.0". A map used for something — the index of a key-value store — rather than shown for its own sake. - ***Effective Rust*** (David Drysdale, O'Reilly 2024), ch. 2 "Traits" → Item 10 "Familiarize yourself with standard traits" → the **"PartialEq and Eq"** and **"Hash"** subsections: what deriving each one promises, and why the two must agree — the contract every key on these pages signs. [Free online ↗](https://effective-rust.com/std-traits.html).
- ***Rust: The Practical Guide*** (Nouman Azam, Rheinwerk 2025), ch. 5 → **§5.5 "HashMaps"** and **§5.6 "HashSets"**. - ***Rust for Rustaceans*** (Jon Gjengset, No Starch 2021) has no section on hash maps — `HashMap` appears 22 times in the text, in passing — so it is not on this list; the library's [chapter map](../../10_Resources/rust_for_rustaceans/README.md) says what it does cover.

## std, the Reference and the crate underneath

- [`HashSet` ↗](https://doc.rust-lang.org/std/collections/struct.HashSet.html): *"A hash set implemented as a `HashMap` where the value is `()`"*, the sentence [A first `HashSet`](../a_first_hashset/README.md) leans on, then [`insert` ↗](https://doc.rust-lang.org/std/collections/struct.HashSet.html#method.insert) (returns whether the value was newly inserted), [`contains` ↗](https://doc.rust-lang.org/std/collections/struct.HashSet.html#method.contains), [`remove` ↗](https://doc.rust-lang.org/std/collections/struct.HashSet.html#method.remove), [`take` ↗](https://doc.rust-lang.org/std/collections/struct.HashSet.html#method.take), and the four operations [`union` ↗](https://doc.rust-lang.org/std/collections/struct.HashSet.html#method.union), [`intersection` ↗](https://doc.rust-lang.org/std/collections/struct.HashSet.html#method.intersection), [`difference` ↗](https://doc.rust-lang.org/std/collections/struct.HashSet.html#method.difference) and [`symmetric_difference` ↗](https://doc.rust-lang.org/std/collections/struct.HashSet.html#method.symmetric_difference).
- [`hash_map::Entry` ↗](https://doc.rust-lang.org/std/collections/hash_map/enum.Entry.html): the two variants, [`Occupied` ↗](https://doc.rust-lang.org/std/collections/hash_map/enum.Entry.html#variant.Occupied) and [`Vacant` ↗](https://doc.rust-lang.org/std/collections/hash_map/enum.Entry.html#variant.Vacant), and the methods that close them: [`or_insert` ↗](https://doc.rust-lang.org/std/collections/hash_map/enum.Entry.html#method.or_insert), [`or_insert_with` ↗](https://doc.rust-lang.org/std/collections/hash_map/enum.Entry.html#method.or_insert_with), [`or_default` ↗](https://doc.rust-lang.org/std/collections/hash_map/enum.Entry.html#method.or_default) and [`and_modify` ↗](https://doc.rust-lang.org/std/collections/hash_map/enum.Entry.html#method.and_modify). The two variant structs, [`OccupiedEntry` ↗](https://doc.rust-lang.org/std/collections/hash_map/struct.OccupiedEntry.html) and [`VacantEntry` ↗](https://doc.rust-lang.org/std/collections/hash_map/struct.VacantEntry.html), are what the `{:?}` output on the lesson page shows.
- [`hash_map::RandomState` ↗](https://doc.rust-lang.org/std/collections/hash_map/struct.RandomState.html) (also at [`std::hash::RandomState` ↗](https://doc.rust-lang.org/std/hash/struct.RandomState.html)): the default `BuildHasher`, seeded from the OS's random source once per thread, which is why [five runs print five orders](../a_first_hashmap/README.md#8-iterating-and-why-the-order-is-not-the-insertion-order). The [`std::hash` ↗](https://doc.rust-lang.org/std/hash/index.html) module page shows a hand-written `Hash` impl and states the `Eq` contract.
- [`Hash` ↗](https://doc.rust-lang.org/std/hash/trait.Hash.html) and [`Eq` ↗](https://doc.rust-lang.org/std/cmp/trait.Eq.html): *"`k1 == k2` implies `hash(k1) == hash(k2)`"* on the first, and on the second the three laws — reflexive, symmetric, transitive — that `f64`'s `NaN` breaks, which is [entry 18 of the errors page](../hashmap_errors/README.md#18-an-f64-key).
- [`Borrow` ↗](https://doc.rust-lang.org/std/borrow/trait.Borrow.html): the trait behind `get<Q>` where `K: Borrow<Q>`, with `HashMap` as its worked example — why `HashMap<String, V>` answers `get("k")` and `HashMap<&str, V>` refuses `get(&some_string)` ([entry 9](../hashmap_errors/README.md#9-str-keys-looked-up-with-a-string)). The library's [`Borrow` lesson](../../12_Traits/borrow_trait/README.md) runs it.
- [`BTreeMap` ↗](https://doc.rust-lang.org/std/collections/struct.BTreeMap.html) and [`BTreeSet` ↗](https://doc.rust-lang.org/std/collections/struct.BTreeSet.html): the ordered pair, `Ord` instead of `Hash`, and the `range` query a hash map cannot answer. The lesson here is [`BTreeMap` and `BTreeSet`](../sorted_collections/README.md).
- [`hashbrown` ↗](https://docs.rs/hashbrown/latest/hashbrown/) ([source ↗](https://github.com/rust-lang/hashbrown)): the crate whose table has been std's `HashMap` since Rust 1.36, published on its own with a different default hasher. Its README names the design it ports: Google's [Swiss Tables ↗](https://abseil.io/about/design/swisstables), whose design notes explain the control bytes and the SIMD probe. Matt Kulukundis presented that design at [CppCon 2017: *Designing a Fast, Efficient, Cache-friendly Hash Table, Step by Step* ↗](https://www.youtube.com/watch?v=ncHmEUmJZf4) (1 h); the title was checked, the video was not watched here. The general idea, before any of that, is [Wikipedia's *Hash table* ↗](https://en.wikipedia.org/wiki/Hash_table).

## Read with care

- ***Rust: The Practical Guide*, §5.5, on `contains_key`.** *"The function returns an Option wrapping the value inside Some if the key exists, and None, otherwise."* Run on rustc 1.98.0, `word_counts.contains_key("Programming")` is `true` and `type_name_of_val` of it prints `bool`; the method that returns `Option<&V>` is `get`. Recorded by [`first_hashmap_claims.rs`](../a_first_hashmap/examples/first_hashmap_claims.rs).
- ***Rust: The Practical Guide*, §5.5 and §5.6, printing the map and the set.** Both sections read their result off `println!("{:?}", word_counts)` and `println!("{:?}", words)`. The count shown is right; the order is not a property of the program. The book's four-entry map, compiled once and run five times, printed [five different orders](../a_first_hashmap/README.md#8-iterating-and-why-the-order-is-not-the-insertion-order). Sort, or use a `BTreeMap`, before reading anything off a printout.
- **Any page that says "constant time" without "expected".** std's own table writes `O(1)~`, with the tilde, because a lookup that hits a long probe sequence or a table resize costs more; the average is constant, the worst case is not. The Book's and RBE's pages avoid the claim; the *Practical Guide*'s *"extremely fast"* is not wrong, just unmeasured, and it is marked *not checked* on the lesson page.
