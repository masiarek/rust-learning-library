# Step 2: Some types have no size

[How to learn `ToOwned`](../README.md) › **Step 2 of 10** · back: [Step 1 — `ToOwned` is `Clone` with a separate owned type](../clone_vs_to_owned/README.md) · next: [Step 3 — Owned and borrowed are two different types](../owned_and_borrowed_types/README.md)

**Level:** 101 · a step on a learning path

**One line:** `str`, `[T]` and `Path` have no size known at compile time, so you never hold one — only a pointer to one, such as `&str` or `Box<str>`, and that pointer carries the length as a second word. It is the reason `str` cannot be `Clone`, and so the reason `ToOwned` exists.

## A `str` is a run of bytes whose length is not in its type

`"hi"` and `"hello"` are both `str`: one is 2 bytes, the other 5. A type whose values come in different sizes cannot go in a variable, cannot be returned by value and cannot be passed by value, because each of those needs one number of bytes, fixed when the code is compiled. So `let x: str = *s;` and `size_of::<str>()` are both refused with `E0277`, *"the size for values of type `str` cannot be known at compilation time"* (rustc 1.98.0).

Such a type is **dynamically sized** — a *DST*, or *unsized* type. You cannot hold one. You can hold a pointer to one.

## So the length moves into the pointer

A pointer to a sized type is one word: the address. A pointer to an unsized type is two: the address and the length, which is what the type could not carry. That is a **wide pointer** — the glossary calls it a *fat pointer*. The checkpoint below measures it in words rather than bytes, so the answer is the same on a 32-bit target.

| Unsized type | Pointers you hold | Second word | Owned twin, [step 3](../owned_and_borrowed_types/README.md) |
|---|---|---|---|
| `str` | `&str`, `Box<str>`, `Rc<str>` | length in bytes | `String` |
| `[T]` | `&[T]`, `Box<[T]>` | length in elements | `Vec<T>` |
| `Path` | `&Path` | length in bytes | `PathBuf` |
| `OsStr`, `CStr` | `&OsStr`, `&CStr` | length | `OsString`, `CString` |
| `dyn Trait` | `&dyn Trait`, `Box<dyn Trait>` | a vtable pointer | none — see [Returning a trait](../../returning_a_trait/README.md) |

## `Sized` is the bound you never wrote

Every type parameter means `T: Sized` unless it says `T: ?Sized`. Two declarations make this step matter for the rest of the path:

- `pub trait Clone: Sized` — a type with no size cannot be `Clone`, because `clone` returns `Self` by value. [Step 4](../clone_returns_self/README.md) is that half.
- `pub trait ToOwned` — no `Sized`, so `impl ToOwned for str` is allowed, and it can return a sized `String` instead. [Step 1](../clone_vs_to_owned/README.md) is that half.

## What this step sets up

- [Step 3](../owned_and_borrowed_types/README.md): if nobody can hold a `str`, something sized has to own the bytes — that is `String`.
- [Step 4](../clone_returns_self/README.md): `Clone: Sized` rules `str` out, which is the gap `ToOwned` fills.
- [Step 10](../implementing_it_or_not/README.md): the only good home for your own `ToOwned` impl is an unsized type of your own, `struct Sorted<T>([T])`.

## Po polsku

`str`, `[T]` i `Path` to typy **bez znanego rozmiaru** (*dynamically sized types*): `"hi"` ma 2 bajty, `"hello"` — 5, a oba są typu `str`. Takiej wartości nie da się trzymać w zmiennej ani zwrócić przez wartość, więc zawsze stoi za wskaźnikiem — `&str`, `Box<str>` — a ten wskaźnik ma dwa słowa: adres i długość (*wide pointer*, potocznie *fat pointer*).

Stąd cała reszta ścieżki: `Clone` wymaga `Sized`, więc `str` nie może być `Clone`. `ToOwned` tego wymogu nie ma — dlatego `impl ToOwned for str` jest dozwolone i zwraca `String`, typ o stałym rozmiarze.

**Szukaj po polsku:** typy o dynamicznym rozmiarze · `rust ?Sized` · `rust fat pointer str`
