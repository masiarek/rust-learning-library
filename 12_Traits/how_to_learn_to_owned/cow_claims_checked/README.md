# What `Cow` explanations get wrong, run

[How to learn `ToOwned`](../README.md) › **Beside the steps** · read after: [Step 7 — `Borrow` is the way back](../borrow_the_way_back/README.md)

**Level:** 201 · a companion to the path

**One line:** Most explanations of `Cow` get the enum right and a method, a signature or a cost wrong. Ten claims that turn up again and again — in articles, book chapters, chat answers and diagrams — each checked against rustc 1.98.0, eight by a program and two by the compiler's refusal.

## The type, before the claims

```rust
pub enum Cow<'a, B>
where
    B: 'a + ToOwned + ?Sized,
{
    Borrowed(&'a B),
    Owned(<B as ToOwned>::Owned),
}
```

Everything below follows from four facts in those six lines. `Borrowed` holds a *reference* to `B`, not a `B`. `Owned` holds `B`'s **owned twin** — `String` for `B = str`, from [step 1](../clone_vs_to_owned/README.md) — not a `B`. `?Sized` *allows* an unsized `B`, it does not require one ([step 2](../types_with_no_size/README.md)). And nothing in it is a trait object: reading a `Cow` is a `match`, not a virtual call.

## Two claims the compiler refuses

**"`Cow` has `into_owned` and `into_borrowed`."** There is no `into_borrowed`. rustc 1.98.0: *"no method named `into_borrowed` found for enum `Cow<'_, str>` in the current scope"* (`E0599`). Nor is there a stable `is_borrowed` method — `cow.is_borrowed()` is `E0599` too — so on stable you ask with `matches!(cow, Cow::Borrowed(_))`. The one conversion out of a `Cow` is `into_owned`.

**"`?Sized` means trait objects can go in a `Cow`."** `Cow<'_, dyn Display>` is `E0277`: *"the trait bound `dyn std::fmt::Display: ToOwned` is not satisfied"*. A trait object has no owned twin — `Clone` cannot be called through `dyn` — so the blanket impl from [step 6](../the_blanket_to_owned/README.md) does not reach it. The `?Sized` is there for `str`, `[T]`, `Path`, `OsStr` and `CStr`.

Reading them in order:

1. **`to_mut()` returns `&mut <B as ToOwned>::Owned`** — a `&mut String` for a `Cow<str>`, which is why you can `push_str` through it. Explanations that say `&mut B` or `&mut str` describe a method you could not push into. [Step 7](../borrow_the_way_back/README.md) runs it twice.
2. **Methods reached through `Deref` never touch the `Cow`.** `replace` and `to_uppercase` are `str`'s methods; they borrow the text and return a new `String`, and the `Cow` stays `Borrowed`. What changes the variant is a call on the `Cow` itself: `to_mut()`, or an operator it implements, such as the `+=` in claim 6. `into_owned()` does not change it — it consumes the `Cow` and hands back the `String`.
3. **`as_ref()` is `AsRef<str>`, and returns a `&str`**, the same thing `&*cow` gives you.
4. **`Owned` means owned, not cloned.** A `String` handed to `.into()` becomes `Owned` without a copy; a `&'static str` becomes `Borrowed`. That pair is how the usual error-message function returns `"out of memory".into()` from most arms and `format!(…).into()` from the one that needs data.
5. **`B` may be sized**, and a `Cow<i32>` compiles. As for size: `Cow<str>` is exactly a `String` — [the tag is free](../../../18_Ownership/clone_on_write/README.md#the-tag-is-free) — but it is a word more than the `&str` it replaces, and a `Cow<i32>` is twice an `&i32`. "Possible size increase" is fair *against a reference*, never against the owned type.
6. **`Cow<'a, str>` implements `Add<&str>` and `AddAssign<&str>`**, and `+=` on a `Borrowed` one that already holds text allocates: the result has to own both halves, so the `Cow` becomes `Owned`.
7. **The `capitalize` that circulates allocates for text that is already capitalized, and never capitalizes a non-ASCII letter.** It slices byte `0..1`, which is not a character boundary in `"élan"`, so `get` returns `None` and the text comes back untouched. Asking `chars().next()` whether the first character is lowercase fixes both, and allocates only for `"ada"` and `"élan"`.
8. **`Rc::make_mut` and `Arc::make_mut` are clone-on-write too**, as the `Cow` docs point out: they clone only when the value is shared, and write in place when the count is one.

## One warning to act on

Almost every example online writes `fn f(input: &str) -> Cow<str>`. On rustc 1.98.0 that compiles with a warning, *"hiding a lifetime that's elided elsewhere is confusing"*. The return type borrows from `input`, and the signature should say so: `-> Cow<'_, str>`. Every example in this library does.

## Po polsku

`Cow` łatwo opisać prawie dobrze. Z definicji wynikają cztery fakty: `Borrowed` trzyma **referencję** do `B`, `Owned` trzyma **posiadanego bliźniaka** `B` (dla `str` — `String`), `?Sized` **pozwala** na typ bez rozmiaru, ale go nie wymaga, a w całym typie nie ma żadnego obiektu cechy — odczyt to zwykłe `match`.

Sprawdzone na rustc 1.98.0: metody `into_borrowed` nie ma (`E0599`); `Cow<dyn Display>` się nie kompiluje (`E0277`); `to_mut()` zwraca `&mut String`, nie `&mut str`; `replace` czy `to_uppercase` wołane przez `Deref` nie zmieniają wariantu; `as_ref()` daje `&str`; `Owned` nie znaczy „sklonowane”; `+=` na `Borrowed` alokuje. Popularna funkcja `capitalize` alokuje nawet dla „Ada” i nigdy nie zmieni „élan”, bo tnie po bajcie, nie po znaku. I drobiazg: sygnatura `-> Cow<str>` daje ostrzeżenie — pisz `-> Cow<'_, str>`.
