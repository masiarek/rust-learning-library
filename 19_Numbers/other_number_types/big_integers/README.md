# Big integers: `BigInt` and Python's `int`

[Other number types](../README.md) › **Big integers**

**Level:** 101 → 201 · for newcomers

**One line:** Every Python `int` grows to fit its value. Rust's widest built-in integer, `u128`, holds 34! and not 35!, and past its 39 digits you need `num::BigInt` or `BigUint`. Those grow like Python's `int` but divide like Rust: `/` truncates toward zero, where Python's `//` floors.

## Where the built-in integers stop

<!-- source:where_u128_runs_out -->
*[`where_u128_runs_out.rs`](examples/where_u128_runs_out.rs) in full — pasted here by `tools/run_examples.py` from the file CI compiles and runs.*

```rust
// Where the widest built-in integers stop, and how they divide a negative.
fn main() {
    let (mut k, mut n) = (1_u64, 1_u64);
    while let Some(next) = n.checked_mul(k + 1) {
        (k, n) = (k + 1, next);
    }
    println!("u64:  {k}! = {n}"); // u64:  20! = 2432902008176640000

    let (mut k, mut n) = (1_u128, 1_u128);
    while let Some(next) = n.checked_mul(k + 1) {
        (k, n) = (k + 1, next);
    }
    println!("u128: {k}! = {n}"); // u128: 34! = 295232799039604140847618609643520000000
    println!("35!: {:?}", n.checked_mul(35)); // 35!: None
    println!("u128::MAX has {} digits", u128::MAX.to_string().len()); // u128::MAX has 39 digits

    // `/` truncates toward zero, and `%` takes the sign of the left operand.
    println!("{} {}", -7 / 2, -7 % 2); // -3 -1
    println!("{} {}", 7 / -2, 7 % -2); // -3 1

    // Euclidean: the remainder is never negative.
    println!("{} {}", (-7_i32).div_euclid(2), (-7_i32).rem_euclid(2)); // -4 1
    println!("{} {}", 7_i32.div_euclid(-2), 7_i32.rem_euclid(-2)); // -3 1
}
```

`checked_mul` returns `None` instead of overflowing, so each loop stops at the last factorial its type can hold: 20! for `u64` and 34! for `u128`. A plain `*` would panic in a debug build and wrap in release, as [Meet the byte](../../meet_the_byte/README.md) measures. A `u128` has 39 decimal digits, and 35! has 41. Python never stops, because its `int` has no width.

## Past the ceiling

```rust title="src/main.rs — cargo 1.98.0, num 0.4.3"
use num::{BigInt, BigUint, Integer};

fn main() {
    let f: BigUint = (1..=100u32).map(BigUint::from).product();
    println!("{}", f.to_string().len());                               // 158
    println!("{}", BigUint::from(2u32).pow(1000).to_string().len());  // 302

    let (a, b) = (BigInt::from(-7), BigInt::from(2));
    println!("{} {}", &a / &b, &a % &b);                  // -3 -1
    println!("{} {}", a.div_floor(&b), a.mod_floor(&b));  // -4 1
}
```

```python title="Python 3.14.7"
import math

print(len(str(math.factorial(100))))  # 158
print(len(str(2 ** 1000)))            # 302

print(-7 // 2, -7 % 2)                # -4 1
print(int(-7 / 2), math.fmod(-7, 2))  # -3 -1.0
```

The sizes agree: 100! has 158 digits and 2¹⁰⁰⁰ has 302 in both languages. `BigUint` is the unsigned one, which is right for a factorial, and `BigInt` carries a sign. Both keep their digits on the heap, so unlike `u128` they are not `Copy`. That is why the division lines borrow with `&a / &b`: a bare `a / b` would move both values into the division.

The last two lines are where a port from Python goes wrong.

## Three ways to divide a negative number

When both operands are positive, every rule gives the same answer. With a negative operand there are three rules, and the two languages use different defaults:

| Rule | `-7` by `2` | `7` by `-2` | Python | Rust `i32` | `num::BigInt` |
|---|---|---|---|---|---|
| **Truncate** toward zero | −3, −1 | −3, 1 | `int(a / b)`, `math.fmod` — through a float | `/` and `%` | `/` and `%` |
| **Floor** toward −∞ | −4, 1 | −4, −1 | `//` and `%` | `div_floor` — unstable on 1.98.0, `E0658` | [`div_floor`, `mod_floor` ↗](https://docs.rs/num-integer/0.1.47/num_integer/trait.Integer.html#tymethod.div_floor) from `Integer` |
| **Euclidean**: the remainder is never negative | −4, 1 | −3, 1 | — | [`div_euclid`, `rem_euclid` ↗](https://doc.rust-lang.org/std/primitive.i32.html#method.div_euclid) | `div_euclid`, `rem_euclid` from `num::traits::Euclid` |

Each pair of numbers is quotient, remainder. Every cell was printed: the `i32` column by the program above, and the `BigInt` and Python columns by the two snippets plus a run of `7` by `-2` with each method.

- **Python's `//` is floor division, and Rust's `/` is not.** Port `(a // b)` to `a / b` and every result with one negative operand is off by one, with no warning.
- **For a positive divisor, Euclidean is floor.** `(-7).div_euclid(2)` and `-7 // 2` are both `-4`. That is the stable std method to use for Python's `//` when the divisor is known to be positive, which covers the usual case: a day of the week, an index into a ring buffer, a bucket number.
- **For a negative divisor, they differ.** `7 // -2` is `-4` and `7_i32.div_euclid(-2)` is `-3`. If you need floor division there, `num`'s `div_floor` does it for both primitives and `BigInt`.
- **`int(a / b)` in Python truncates, but only after a trip through a float.** `10**20 // 3` is `33333333333333333333`, and `int(10**20 / 3)` is `33333333333333331968`. Rust's `/` on integers never touches a float.

## If you are coming from Python

**What transfers:** a `BigInt` is what you think an `int` is. It is exact, it has no ceiling, it parses from a string of any length (`"123456789012345678901234567890".parse::<BigInt>()`), it prints every digit, and arithmetic gets slower as the value gets wider.

**What changes:**

- **The ceiling is the default, and you opt out of it.** In Python you never pick a width. In Rust you pick `i32`, `i64` or `i128`, and each one has a ceiling that a debug build enforces with a panic and a release build ignores. `BigInt` is the explicit choice for "no ceiling" and costs a crate and a heap allocation per value. [What `i128` is exact about](../../../09_Advanced/i128_exactness/README.md) measures what the fixed widths cost.
- **Division truncates.** `-7 // 2` is `-4` in Python. `BigInt::from(-7) / BigInt::from(2)` is `-3`, the same as Rust's primitives, so `num` kept Rust's rule, not Python's. Use `div_floor` from `num::Integer`.
- **Not `Copy`.** An `int` in Python is a reference to an immutable object, so `b = a` costs nothing and changes nothing. A `BigInt` moves on assignment, like a `String`. Borrow with `&a + &b`, or `.clone()` when you mean a copy. See [`Copy` vs `Clone`](../../../16_Structs/copy_vs_clone/README.md).
- **Converting back can fail.** `u64::try_from(big)` returns a `Result`, and a value one past `u64::MAX` gives `Err(TryFromBigIntError { original: 18446744073709551616 })`. Python's `int` has no narrower type to convert back to.

## Po polsku

Pythonowy `int` rośnie bez końca — nie ma szerokości, więc nie ma przepełnienia (*overflow*). W Ruscie największy wbudowany typ całkowity, `u128`, mieści 39 cyfr: 34! się zmieści, 35! już nie. Dalej trzeba sięgnąć po `num::BigInt` (ze znakiem) albo `BigUint` (bez znaku), czyli liczby całkowite dowolnej precyzji (*arbitrary precision*), trzymane na stercie.

Pułapka przy przepisywaniu kodu z Pythona to **dzielenie liczb ujemnych**. Pythonowe `//` zaokrąga w dół, do minus nieskończoności (*floor*): `-7 // 2` to `-4`. Rustowe `/` obcina w stronę zera (*truncate*): `-7 / 2` to `-3` — i `BigInt` robi tak samo. Odpowiednikiem `//` jest `div_floor` z `num::Integer`, a przy dodatnim dzielniku także stabilne w std `div_euclid`. Samo `i32::div_floor` jest w Ruscie 1.98.0 wciąż niestabilne (`E0658`).

**Szukaj po polsku:** duże liczby całkowite Rust · `rust bigint factorial` · dzielenie całkowite liczb ujemnych · `rust div_euclid python floor division`
