# Flow control: what each construct evaluates to, and how far each exit jumps

**Level:** 101 · for newcomers

**One line:** Rust has two branches (`if`, `match`), three loops (`for`, `while`, `loop`) and five ways out (`continue`, `break`, `break 'label`, `return`, `?`). Every one of the first five is an **expression** with a value and a type, and every way out jumps a fixed distance you can read off the keyword.

This page is the map of the section: one program that runs each construct once, and a folder per construct for the details.

## Every construct is an expression

```rust
let n = 7;
let size = if n < 10 { "small" } else { "large" };   // "small"
let parity = match n % 2 { 0 => "even", _ => "odd" }; // "odd"
let mut tries = 0;
let found = loop { tries += 1; if tries == 3 { break tries * 10; } }; // 30
```

| Construct | Evaluates to | Lesson |
|---|---|---|
| `if … else` | the value of the branch that ran; both branches must have the same type | [`if` expressions](../if_expressions/README.md) |
| `match` | the value of the arm that matched; every arm the same type, and every case covered | [`match` expressions](../match_expressions/README.md) |
| `for` | always `()` | [`for` loops](../for_loops/README.md) |
| `while` | always `()` | [`while` loops](../while_loops/README.md) |
| `loop` | the value handed to `break`, or `!` when nothing breaks | [`loop`](../the_loop_keyword/README.md) |
| `'label: { … }` | the value handed to `break 'label`, or the block's last expression | [Loop labels](../loop_labels/README.md) |

`for` and `while` cannot produce a value because they can end without a `break`: a range can be empty and a condition can be false on the first check, and then there would be no value to hand over. `loop` has no such exit, so `break value` is allowed there and in a labelled block, and nowhere else.

The rule under all of this is [a block is an expression](../../15_First_Programs/a_block_is_an_expression/README.md): a `{ }` has the value of its last line without a semicolon.

## Every way out jumps a known distance

| Exit | Where control goes | Works in | Carries a value | Lesson |
|---|---|---|---|---|
| `continue` | the next pass of the innermost loop | `for`, `while`, `loop` | no | [`continue`](../continue_expressions/README.md) |
| `continue 'label` | the next pass of the labelled loop | `for`, `while`, `loop` | no | [Loop labels](../loop_labels/README.md) |
| `break` | past the end of the innermost loop | `for`, `while`, `loop` | only in `loop` | [`break`](../break_expressions/README.md) |
| `break 'label` | past the end of the labelled loop or block | loops and labelled blocks | only in `loop` and blocks | [Loop labels](../loop_labels/README.md) |
| `return` | out of the function, through every loop | anywhere in a function body | the function's return value | [Functions](../functions/README.md) |
| `?` | out of the function when the value is `Err` or `None` | a function returning `Result` or `Option` | the error | [The `?` operator](../../17_Option_and_Result/the_question_mark_operator/README.md) |

A panic and `std::process::exit` leave too, further still: the first unwinds the thread, the second ends the process. None of these is `goto` — Rust has no jump to an arbitrary line. Every exit in the table [drops](../../12_Traits/drop_and_raii/README.md) the values in scope on the way out, and so does an unwinding panic; `process::exit` is the exception, and runs no destructors at all.

Reading it:

- **Section 1, the types.** The two branches produced a `&str`; `for` and `while` produced `()`, even though the `for` did real work (the sum, 28, lives in a `mut` outside it). The `loop` and the labelled block produced an `i32` through `break`.
- **Section 2, the distances.** `continue` kept looping and skipped the odd readings. `break` stopped at 8, the first reading over 6, so only 3 was seen. `break 'rows` left both loops at `(2, 3)`, where a plain `break` would have left only the inner one and let `a` carry on to 3 and 4. `return` left the loop and `first_even` together, and `?` left `total` at `"x"` without reading `"3"`.

## Which one to reach for

- **Two outcomes of a condition** → `if`. **Several outcomes of one value** → `match`, which also tells you when you forgot one.
- **You know the sequence** (a range, a collection, an iterator) → `for`. **You know only a condition** → `while`. **You know neither** → `loop`, left by `break` or `return`.
- **You need a value out of a search** → an iterator method (`find`, `position`, `any`) first; then `loop` with `break value`, or a labelled block.
- **You want the index** → usually you don't: [loops without an index](../loops_without_an_index/README.md).

## The pattern-driven forms live elsewhere

`if let`, `while let` and `let else` are flow control driven by a pattern rather than a `bool`, and they are taught from the `Option` side: [`if let`](../../17_Option_and_Result/if_let/README.md), [`while let`](../../17_Option_and_Result/while_let/README.md), [`let else`](../../30_Pattern_Matching/let_else/README.md). What rustc turns a `for` and a `?` into — a `loop` inside `match`es — is printed on [Printing the HIR](../../20_Compilers/printing_the_hir/README.md).

## If you are coming from another language

- **Python.** The same five constructs, with three changes. `if` has a value, so `a if c else b` becomes `if c { a } else { b }`. `match` (Python 3.10+) is a statement there and is not checked for completeness; here it has a value and a missing case is a compile error. And the `for … else` / `while … else` clause does not exist — the Rust answer to "did the loop finish without breaking?" is a `loop` or labelled block that breaks with a value, or `iter().find()`. Python has no labelled `break`; the flag variable you would write there is what `break 'label` replaces.
- **C.** `for (init; cond; step)` has no counterpart: a Rust `for` walks an iterator, and a counting loop is `for i in 0..n`. `switch` becomes `match`, with no fall-through and no `break` between arms. There is no `do … while` (write `loop` with a `break` at the bottom) and no `goto`; the jump-to-cleanup idiom is replaced by `Drop`, which runs on every exit in the table. And a condition must be a `bool`: `while n` on an integer is `E0308`, where C reads it as `n != 0`.
- **ABAP.** `IF … ELSEIF … ELSE … ENDIF` and `CASE … WHEN … WHEN OTHERS … ENDCASE` are statements, so the closer match for Rust's `if` and `match` is the constructor expressions `COND #( WHEN … THEN … ELSE … )` and `SWITCH #( … )`, which have values. `DO n TIMES` is `for _ in 0..n`, `WHILE … ENDWHILE` is `while`, and `DO … ENDDO` with `EXIT` is `loop` with `break`. `EXIT` and `CONTINUE` leave or skip the innermost loop only, as in Rust; what Rust adds is the label to name an outer one. `CHECK cond` inside a loop is `if !cond { continue; }`. The loop counter `sy-index` has no counterpart — ask for it with `.enumerate()`.

## Po polsku

W Ruscie jest pięć konstrukcji sterujących przepływem — dwa rozgałęzienia (`if`, `match`) i trzy pętle (`for`, `while`, `loop`) — i każda z nich jest **wyrażeniem**, czyli ma wartość i typ. `if` i `match` dają wartość gałęzi, która się wykonała. `for` i `while` zawsze dają `()`, bo mogą się skończyć bez `break`: zakres bywa pusty, a warunek fałszywy już przy pierwszym sprawdzeniu, i wtedy nie byłoby czego zwrócić. `loop` takiego wyjścia nie ma, dlatego tylko w nim (i w bloku z etykietą) wolno napisać `break wartość`.

Wyjść z konstrukcji jest pięć i każde skacze na znaną odległość: `continue` — do następnego obiegu najbliższej pętli; `break` — za koniec najbliższej pętli; `break 'etykieta` — za koniec pętli lub bloku oznaczonego etykietą; `return` — z całej funkcji, przez wszystkie pętle naraz; `?` — z funkcji, gdy wartość to `Err` albo `None`. Instrukcji `goto` nie ma wcale, a sprzątanie, do którego w C służył skok do etykiety, robi `Drop`, wywoływany przy każdym z tych wyjść. Programistę ABAP-a ucieszy, że `EXIT` i `CONTINUE` działają tak samo — dotyczą tylko najbliższej pętli — a Rust dokłada do nich etykietę, która pozwala wskazać pętlę zewnętrzną.
