# What a smart pointer costs

[Smart pointers](../README.md) › **What it costs**

**Level:** 201 → 301 · working knowledge

**One line:** The handle is free — `Box<u64>`, `Rc<u64>` and `Arc<u64>` are each one word, and `Option` of any of them is still one word — but the work is not: `Rc::new(7u64)` allocates 24 bytes, every `clone` changes a count at run time, and a `RefCell` carries a flag it checks on every borrow.

```rust
use std::mem::size_of;
use std::rc::Rc;

fn main() {
    println!("{}", size_of::<Rc<u64>>());          // 8 — one pointer
    let shared = Rc::new(7u64);                    // one allocation: 24 bytes
    let second = Rc::clone(&shared);               // no allocation; a count goes 1 -> 2
    println!("{}", Rc::strong_count(&second));     // 2
}
```

## Zero-cost means "no worse than by hand", not "gone"

A zero-cost abstraction costs nothing *beyond* the code you would have written yourself. For `Box` that holds exactly: section 1 of the run shows `Box<u64>` is 8 bytes, the size of the `*const u64` you would have kept, and `Option<Box<u64>>` is still 8 because `Box` is built on a non-null pointer ([Nullable pointers](../../17_Option_and_Result/nullable_pointers/README.md)). `Rc`, `Arc` and `Weak` are the same one word.

What is not zero is the job each type does. The run counts it with a `#[global_allocator]` that passes every request to `System` and tallies it on the way — the technique from [The global allocator](../../09_Advanced/the_global_allocator/README.md).

## Making one

| Expression | Allocations | Bytes | Why that many |
|---|---|---|---|
| `Box::new(7u64)` | 1 | 8 | the `u64` |
| `Rc::new(7u64)` | 1 | 24 | a strong count, a weak count, then the `u64` |
| `Arc::new(7u64)` | 1 | 24 | the same three words, with atomic counts |
| `String::from("hello")` | 1 | 5 | the bytes; the length and capacity live in the handle |
| `Vec::<u32>::with_capacity(4)` | 1 | 16 | room for four `u32` |
| `Cow::Borrowed("hello")` | 0 | 0 | it points at the literal |
| `RefCell::new(5i32)` | 0 | 0 | not a pointer at all — the flag sits beside the value |

`Rc`'s 24 bytes are its private `RcInner<T>`: in the 1.98.0 source (`alloc/src/rc.rs`), a `strong: Cell<usize>`, a `weak: Cell<usize>` and the `value: T`, and an `Rc<T>` holds a `NonNull` to that.

## Sharing one, and letting go

Sections 3 and 4 of the run:

- `Rc::clone` allocates nothing and moves the strong count from 1 to 2. That is why [`Rc::clone` is the cheapest `.clone()` in Rust](../../18_Ownership/reference_counting/README.md) — and also why it is not free: a count is written on every clone and every drop.
- `Rc::downgrade` allocates nothing and moves the weak count to 1.
- Dropping the second `Rc` frees nothing. Dropping the last `Rc` drops the value and still frees nothing — `weak.upgrade()` is `None`, yet the 24 bytes stay, because the weak count lives in them.
- Dropping the last `Weak` is the one `free`.

`Arc` does the same with atomic operations, which is what lets it cross threads and what makes each count change more expensive than `Rc`'s. The run does not time it; a count change is too small to time with a single measurement, which [Timing a block](../../33_Time_and_Benchmarking/timing_a_block/README.md) explains.

## `RefCell` pays in a flag and a check

`size_of::<RefCell<i32>>()` is 16 where `i32` is 4: the `RefCell` keeps a borrow counter beside the value, padded to 8 bytes. Every `borrow()` and `borrow_mut()` reads and writes it, and a conflicting borrow is found at run time — `try_borrow_mut` returns `Err(BorrowMutError)` while a `Ref` is alive, and `borrow_mut` would panic. `Cell<i32>` is 4 bytes: it never hands out references, so it has nothing to count. [Interior mutability](../../09_Advanced/interior_mutability/README.md) is the page for choosing between them.

## Can the optimizer remove the allocation?

It is allowed to. std's [`GlobalAlloc` ↗](https://doc.rust-lang.org/std/alloc/trait.GlobalAlloc.html) docs say you must not rely on allocations actually happening: the optimizer may remove an unused one or move it to the stack. In this program it did not — built with `rustc -C opt-level=3` on rustc 1.98.0, every line of the output was identical to the unoptimized run. That is a measurement of this program, not a promise about yours.

## If you are coming from another language

- **C++.** `std::make_shared<T>` allocates the control block and the value together, which is `Rc::new`'s single 24-byte allocation; `std::shared_ptr<T>(new T)` is two allocations, and Rust has no spelling for that. `shared_ptr` counts atomically always, so it is `Arc`; `Rc` is the non-atomic count C++ does not offer in the standard library.
- **Python.** Every object carries its reference count in its header, so CPython pays the `Rc` cost on every value, and a `sys.getsizeof(0)` of 28 bytes on a 64-bit build includes it. Rust charges the count only to the values you put in an `Rc`.
- **Java, C#, Go.** A tracing garbage collector has no count to update on copy, and pays instead in collection pauses and memory headroom; `Box` has neither cost and `Rc` has the count but no collector — which is why an `Rc` cycle leaks, as [the `Rc` page](../../18_Ownership/reference_counting/README.md) shows.

## Po polsku

„Zerowy koszt” (*zero-cost abstraction*) znaczy „nie drożej niż ręcznie”, a nie „nic”. Sam uchwyt jest darmowy: `Box<u64>`, `Rc<u64>` i `Arc<u64>` mają po 8 bajtów, a `Option` z każdego z nich też 8. Kosztuje praca, którą typ wykonuje w czasie działania programu.

Licznik alokacji pokazuje to wprost: `Box::new(7u64)` prosi o 8 bajtów, `Rc::new(7u64)` o 24 (licznik silnych odwołań, licznik słabych i wartość), `Rc::clone` nie alokuje, ale zmienia licznik z 1 na 2. Ostatni `Rc` niszczy wartość, lecz pamięć zwalnia dopiero ostatni `Weak`, bo licznik słabych odwołań mieszka w tej samej alokacji. `RefCell<i32>` zajmuje 16 bajtów zamiast 4 — obok wartości trzyma licznik pożyczek i sprawdza go przy każdym `borrow()`.

Optymalizator może usunąć nieużywaną alokację i dokumentacja `GlobalAlloc` zabrania na niej polegać; w tym programie z `-C opt-level=3` wynik był identyczny.
